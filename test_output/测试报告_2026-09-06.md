## 一、发现的根因与修复

**根因**: `desktop_app.py` 源码从磁盘和 git 均丢失，只剩编译产物 `__pycache__/desktop_app.cpython-313.pyc`（30KB）。双击 `启动仙人掌.lnk` 因目标文件不存在而静默失败。

**修复**: 从 `.pyc` 反编译还原结构，重建 `desktop_app.py`:
- `TitleBar` — 自定义无边框标题栏（最小化/最大化/关闭/拖动）
- `QtBridge` — 向 gui.html 注入轻量桥对象（主题同步）
- `XianRenZhangWindow` — QWebEngineView 容器，自动探测并启动后端
- 后端自动启动逻辑：检测 8888 端口未占用时启动 `terminal.py`

**验证**: `QT_QPA_PLATFORM=offscreen python desktop_app.py` 正常启动，输出 `[仙人掌壳] 已加载 GUI`

### 2. 发送失败 "Failed to fetch"
**根因**: 原 `terminal.pyc`（源码丢失）的 HTTP handler 是 `BaseHTTPRequestHandler`，不处理 `OPTIONS` 预检请求。浏览器对 JSON POST 先发 OPTIONS 预检 → 收到 501 → 浏览器拦截真实 POST → 前端报 "Failed to fetch"。

**修复**: 创建 `terminal.py` CORS 包装器:
```python
# terminal.py 新增 do_OPTIONS 处理
def _do_options(self):
    self.send_response(200)
    self.send_header("Access-Control-Allow-Origin", "*")
    self.send_header("Access-Control-Allow-Methods", "GET, POST, OPTIONS, PUT, DELETE")
    self.send_header("Access-Control-Allow-Headers", "Content-Type, Authorization, X-Requested-With")
    self.send_header("Access-Control-Max-Age", "86400")
    self.end_headers()

# 通过 exec() 运行 terminal.pyc 字节码（避免 importlib 的 __main__ 限制）
with open("terminal.pyc", "rb") as f:
    f.read(16)
    code = marshal.load(f)
mod = types.ModuleType("__main__")
exec(code, mod.__dict__)
```

**验证**: 
```python
# Python 直连测试
OPTIONS /command → 200, Access-Control-Allow-Origin: * ✓
POST /command → 200, accepted ✓
```

### 3. AI 调用失败 "Target page, context or browser has been closed"
**根因**: `browser.py` 的 `send_message()` 只检查 `self._page is None`。当页面被意外关闭但引用未置空时，`textarea.click()` 抛 `Target page has been closed`。

**修复**: 在 `browser.py` 添加 `_ensure_page()` 存活自检 + 崩溃自动重建:
```python
async def _ensure_page(self, url=DEEPSEEK_URL):
    dead = False
    if self._page is None:
        dead = True
    else:
        try:
            if self._page.is_closed():
                dead = True
                self._page = None
        except Exception:
            dead = True
            self._page = None
    if dead:
        logger.warning("检测到页面已死，自动重建...")
        await self.navigate(url)
    if self._page is None:
        raise RuntimeError("页面重建失败")
    return self._page
```

同时 `send_message()` 和 `_send_internal()` 增加重试机制。

**验证**: 重启后端后发送消息不再出现此错误

---

### 4. 豆包平台发送超时
**根因**: `platform_browser.py` 第 810 行 `click(timeout=5000)` 过短，豆包的输入框是 `div.tiptap.ProseMirror`，首次加载或页面重建后需更长时间。

**修复**: 放宽超时 + 回退到 focus+fill:
```python
try:
    await input_el.wait_for(state="visible", timeout=15000)
except:
    logger.warning("输入框15s内未可见，仍尝试填写")
await input_el.click(timeout=15000)
except Exception as e:
    logger.warning(f"click 失败，改 focus+fill: {e}")
    await input_el.focus(timeout=5000)
```

## 五、已知遗留问题

1. **豆包子代理 click 超时**: `platform_browser.py:1179` 的 `click(timeout=5000)` 在子代理场景下有时不够。可进一步放宽到 15s 或改用 `force=True`。
2. **多平台连续发送稳定性**: 当前测试结果依赖单个 platform 的独立会话。多平台快速切换时可能遇到浏览器上下文复用问题。
