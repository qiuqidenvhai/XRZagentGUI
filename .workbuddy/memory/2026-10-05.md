- registry 路径用 `xrz_paths.XRZ_AGENT_DIR / "conversation_artifacts.json"`。
- `import json as _json` / `import re as _re` 局部 import（模块顶部没有 re/json）。

**验证**（后端重启后 import-time 生效）：

## 端到端真机又抓出第 3 个根因：新对话产物不进产物栏（已修）
- **现象**：新对话发任务，产物文件已落盘 `gui_session/e2e_scope_test.txt`，但 registry 里**没有该真会话的 bucket** → 产物栏空、`/status` 显示"本次任务产物：0 个"。
- **根因（两套 id 不一致）**：前端 `recordArtifactsFromTool()`（gui.html 2271 行）用 `activeTaskId || CURRENT_TASK_ID` 当 `conversation_id` 调 `POST /register_artifacts`，而 `activeTaskId` 是 SSE 的 **`task_<毫秒>` 形式**；但 `/attachments` 查的是后端**真会话 id**（`deepseek_20261005_193808_80030` 这种 `<平台>_<日期>_<时分秒>_<尾数>`）→ 产物登记进了 `task_` 桶，真会话 bucket 空 → 产物栏永远查不到。
- **修法**（`_files_listing_fix.py` 的 `/register_artifacts` 分支，约 1280 行）：id 缺失或 `startswith("task_")` 时，后端用 `_current_conversation_id()`（与 `/status` 同一来源，保证登记与查询同 key）兜底，前端不用改。

## 【坍缩成紫色细线】思考块被 flex 压扁（2026-10-05，用户实机截图）
- **症状**：任务结束后思考块坍缩成一条紫色细线，点不开、浏览不了（用户截图里用户气泡下方那条紫线）。**注意：这不是 09-25/09-26 修过的"内容坍缩"（那是内容被短帧覆盖），这次是 CSS 布局层面整个块被压扁**。
- **根因**：父容器 `.chat-messages` 是 `display:flex; flex-direction:column` + `overflow-y:auto`，**flex 子项默认 `flex-shrink:1`**。消息一多（超高内容），浏览器把 thinking 块纵向压缩到内容高度以下 —— head 文字被块自身的 `overflow:hidden` 裁掉，只剩紫色边框线。CSS 里 `min-height:34px` 救不了（flex 压缩优先于 min-height 的视觉效果）。
- **修法**：给所有消息区 flex 子项加 `flex-shrink: 0`（共 16 处）：`.thinking-block` / `.msg` / `.subagent-block` / `.tool-result`。
- **验证**（`_gui_verify_noshrink.py`，GUI 9333 桥）：塞 40 条长气泡把消息区撑超高（复现触发条件）+ `.done` thinking 块 → `flex-shrink` 计算值 0、`head_h=30`（非线）、`block_h=511`、头部文字"模型推理"未被裁、内容 2000 字符完整。截图亲眼确认同一超高场景下 thinking 块仍正常显示。
- 排查要点：凡是「flex column 容器 + overflow:auto/hidden」里的子项被压扁/只剩边框线，根因都是 flex-shrink 默认 1，加 `flex-shrink:0` 即可。

- 记忆 §沙箱坑 里的 "Path.unlink 被重定向回收站" 之类结论也要按此精神复核：分清"真环境限制" vs "我用的方式不对"。
