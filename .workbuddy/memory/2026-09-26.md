## 关 GUI 没关连带进程（desktop_app.py，已同步 dist）
- **缺陷**：`closeEvent` 旧设计是「关窗只关面板、agent 后台继续跑」，且后端用 `DETACHED_PROCESS` 拉起 → 关 GUI 后留下后端 8888 + 它派生的 playwright node driver + XRZ 专属 chrome（renderer/gpu）+ 子代理，全成孤儿。
- **修复**（desktop_app.py）：新增模块级 `find_backend_pids()`（psutil 按 8888 LISTEN 找后端 PID，多实例）+ `shutdown_backend_and_children(dry_run)`（`taskkill /T /F` 杀整棵 8888 进程树带出 node/chrome/子代理 + `_kill_leftover_browsers()` 二次清扫残留 chrome）；`closeEvent` 改默认调清理，用 `QTimer.singleShot(0, _cleanup_on_close)` 异步不卡 UI；`XRZ_KEEP_BACKEND_ON_CLOSE=1` 可回退旧"后台继续"语义。
- **关键事实**：后端**没有**可远程调用的优雅关闭端点（`/exit //quit //shutdown` 全 404，pyc 里的 `_set_shutdown`/`server_close`/`stop` 是 http.server 内部符号非路由）→ 只能 taskkill 强杀。登录态是磁盘文件（cookies.json + browser_profiles/），强杀进程不丢，重启后端会从磁盘 reload（日志每启一次都"已加载 N 条 cookies"）。taskkill 走 `subprocess` 列表直接调 taskkill.exe，不经 MSYS shell，`/T /F` 不被 Git Bash 吞。
- **真机验证**（`_verify_shutdown_children.py`）：BEFORE 8888=[12568] chrome=9 node=1 → 执行后 8888 全清、node=0、chrome 残留 3 个 2s 内自行退出（主进程被 /T 杀，短命 renderer 自灭）→ 复查残留 0。**注意**：验证会真杀掉当前活跃后端，跑完必须重启后端（`XRZ_NO_GUI=1 python terminal.py`）恢复 8888，否则 agent 离线。
- 验证脚本坑：`find_backend_pids` 用的当前 psutil 与后端进程同机即可，但脚本本身跑在沙箱外解释器，taskkill 真能杀到系统级后端（不像 GUI 桥被沙箱限制）。
