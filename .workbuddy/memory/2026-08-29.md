## 一、修复「GUI 点击发送后任务被吞、无任何反应」（阻塞性）

### 根因链
1. 后端进程已退出（8888 无监听），GUI 页面仍在 → 消息发给空气。
   - `desktop_app.py` 的 `closeEvent` 用 `taskkill /T /F` 杀整棵后端进程树，关窗即退出后端。
   - 工作区里的 `backend_run.log` 显示一次失败的启动：
     `can't open file 'd:\workbuddy工作区\...\terminal.py'` —— 从工作区目录启动导致文件找不到。
     项目内**没有任何代码**写这个 log，是外部（WorkBuddy 会话）误启动留下的痕迹，不是用户日常路径。
2. GUI 静默吞输入：`if (!text || sending) return;` —— `sending` 卡住时无声 return，
   而输入框已被上一行 `inputEl.value = ''` 清空，用户看到"任务被吃了"。
3. `/health` 在后端启动期间就返回 HTTP 200，但 `agent_ready=false`（浏览器初始化约 91 秒），
   只判 `resp.ok` 会误判为可用。

- 发送前**探活**并检查 `agent_ready`：未就绪则提示"仍在启动中（1~2分钟）"，**不清空输入**。
- `sending` 卡住时**明确提示**已等待秒数 + 未发送内容，不再静默 return。
- 失败/超时时**把原文回填输入框**（新增 `sendStartTime` 变量）。
- SSE `onerror`：释放 `sending` 锁 + `setStatus('offline')`；`onopen`：恢复 `online`
  （此前断连后按钮会一直灰着）。

## 六、修复浏览器图标显示为默认 Chrome 图标

### 根因（关键认知）
- Chromium 标题栏是**自绘**的（Views 框架），不理会 `WM_SETICON` —— 代码一直报
  "图标设置成功"，但视觉上没变化。
- **任务栏图标取自「启动时 exe 的资源图标」**，不是窗口图标。
- 所以只发 `WM_SETICON` 永远改不掉，必须改 `chrome.exe` 的图标资源。

### 修复
- 备份：`chromium-1217/chrome-win64/chrome.exe.cactus_backup`、
  `chromium-1234/chrome-win64/chrome.exe.cactus_backup`
- 新增 `patch_chrome_icon.py`：把 `__browser_cactus_icon.ico`（7 尺寸 16~256）
  写入两个 chrome.exe 的 `IDR_MAINFRAME` 图标组（语言 1033，新 RT_ICON id 100~106）
- 验证：7 个尺寸的资源数据与源 .ico **逐字节匹配**；改后浏览器正常启动（exe 未损坏）
- 另：`SHChangeNotify` 刷新 + 清 `IconCache.db` + 重启 explorer，让任务栏立刻显示新图标

### 踩坑记录（PE 图标资源格式）
- 资源里的 `GRPICONDIRENTRY` 是 **14 字节**（末尾是 `WORD nId`，2 字节），
  不是 .ico 文件里的 16 字节 `ICONDIRENTRY`（末尾是 `DWORD dwImageOffset`，4 字节）。
  按 16 解析会 struct 报错。判据：`6 + count*14`（实测 6+8*14=118 完全吻合）。
- 图标组名是**字符串**（`IDR_MAINFRAME`），不是数字 id。
- 替换资源必须指定原语言（1033），否则会「新增」而不是「替换」。

## 二、修复「切换 DeepSeek 失败: 浏览器重启失败: 页面未初始化」

### 根因
- agent_core/browser.py 的 launch() 早返回只看 self._browser is not None，
  没验证浏览器是否真活着。
- 场景：navigate() 检测到 self._page is None（页面已死），但只置了 _page=None，
  没动 _browser 也没停旧 playwright。留下死引用。
- 下次 launch() 看到 self._browser is not None → 直接 return → _page 永远 None → 抛「页面未初始化」。
- 触发链：terminal.py:649 _switch_platform_async → await browser_mgr.navigate() → 抛错。

### 修复
- agent_core/browser.py 的 launch() 增加死引用检测：
  1. 如果 self._browser.is_closed() 抛异常或返回 True → 标记为 dead
  2. dead 时清理 _browser=None + _page=None + 停旧 playwright
  3. 继续走完整启动流程（重新 async_playwright + launch_persistent_context + 拿 page）
  4. 活引用才早返回

### 验证
- 单元逻辑：FakeClosedBrowser → is_closed()=True → dead=True ✔
- 实测：重启后端（PID 16436 → 新进程）→ /health agent_ready=true、browser=connected
- POST /platform deepseek → 返回「已切换到 DeepSeek」，无「页面未初始化」错误 ✔
- 启动日志干净：Playwright 启动 → 持久化上下文 → cookies 加载 → DeepSeek 登录 → Commander 就绪

### 操作命令
- 杀旧后端：MSYS2_ARG_CONV_EXCL='*' taskkill /T /F /PID <pid>
- 启新后端：cd D:/软件/XianRenZhangAgent && XRZ_NO_GUI=1 python terminal.py
